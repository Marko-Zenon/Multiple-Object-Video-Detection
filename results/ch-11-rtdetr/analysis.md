# CH-11 — RT-DETR evidence and technical analysis

Evidence summary prepared for the students (Claude, CH-11 worker for Badabuba). Every number below is read from tracked
files in `results/`, regenerated by `python results/ch-11-rtdetr/make_evidence.py`. AP comes from the project evaluator
(`movd/evaluate.py`): maxDets 500, the frozen ignore policy, curves on `val_fast` (714 frames), headline numbers on all
2,846 `val_full` frames. This file states measurements and the mechanisms that can be checked in the code. **The report's
interpretation and conclusions are left to the students** (TODO prompts at the end).

## 1. Protocol and runs

All RT-DETR runs: COCO-pretrained Ultralytics `rtdetr-l` (sha256 `6de60b10…e73f`, README CH-11 section),
`ultralytics==8.4.207`. Training split `train_rubric`: 2,800 frames x 6 epochs = 16,800 images, imgsz 1344, batch 1, AMP,
seed 42, flip-only augmentation, masked ignore regions. This is the same images-seen budget and input size as the YOLO11s
comparator (CH-09), and per-epoch checkpoints were saved. Hardware: Nazar's RTX 5070 Laptop GPU (8 GB).

| run | changed variable (vs baseline) | status |
|---|---|---|
| `rtdetr_baseline` | none: `optimizer=auto` (AdamW, lr0 0.000833, beta1 0.9, bias warmup from 0.0) | valid |
| `rtdetr_q500` | decoder queries 300 -> 500 (`configs/models/rtdetr-l-q500.yaml`; 941/941 pretrained tensors transferred) | valid |
| `rtdetr_lr1e4_wb0` | peak lr0 0.000833 -> 0.0001 (explicit AdamW, beta1 0.9, `warmup_bias_lr` 0.0) | valid |
| `rtdetr_lr1e4` | lr0 0.0001 **and** bias warmup from 0.1 | **confounded**, kept (`results/rtdetr_lr1e4/README.md`) |

Model size, measured from the checkpoints: RT-DETR-l 32.8 M parameters, YOLO11s (CH-09, 8-class head) 9.4 M parameters
(3.5x). Ultralytics reports 109.9 GFLOPs for RT-DETR-l at its 640 reference size. The budget is therefore equal in images
seen and input size, not in FLOPs.

## 2. G9: does RT-DETR train reliably on 8 GB?

Yes, at batch 1. Every full run finished six epochs with finite losses, no OOM, all six checkpoints and a working resume:

| run | peak allocated / reserved (GB) | train wall time (s) |
|---|---|---|
| rtdetr_baseline | 3.31 / 3.85 | 4,175 |
| rtdetr_q500 | 3.41 / 3.99 | 4,056 |
| rtdetr_lr1e4_wb0 | 3.31 / 3.85 | 4,289 |
| rtdetr_lr1e4 | 3.31 / 3.85 | 4,018 |

Smoke evidence (`results/rtdetr_smoke_*`): batch 2 peaked at 6.3 GB of 8 GB with the same throughput as batch 1
(about 4 img/s), so batch 1 was chosen. This also matches the YOLO11s comparator's batch. Stop-after-epoch and resume were
tested in the smoke run. No protocol value was reduced.

## 4. Convergence (val_fast, one point per 2,800 images)

`figures/learning_curve.png`, `curves.csv`, `convergence.csv`.

| run | epoch 1 | best (epoch) | epoch 6 | epoch 1 as share of best |
|---|---|---|---|---|
| RT-DETR-l baseline | 0.2224 | 0.2691 (3) | 0.2617 | 0.83 |
| RT-DETR-l 500 queries | 0.2359 | 0.2442 (3) | 0.2422 | 0.97 |
| RT-DETR-l lr0 1e-4 | 0.1377 | 0.2271 (4) | 0.2210 | 0.61 |
| RT-DETR-l lr0 1e-4 + bias warmup 0.1 (confounded) | 0.0309 | 0.1568 (6) | 0.1568 | 0.20 |
| YOLO11s baseline | 0.1764 | 0.1845 (2) | 0.1441 | 0.96 |
| Faster R-CNN RPN pre3000 | 0.1844 | 0.1990 (3) | 0.1926 | 0.93 |
| RetinaNet anchors | 0.1611 | 0.1866 (2) | 0.1705 | 0.86 |

Measured facts:
- The RT-DETR baseline is above every CNN curve from epoch 1, peaks at epoch 3 and stays within 0.017 of its peak after that.
  The usual "DETR converges slowly" result (Carion et al. 2020) does not appear for this pretrained RT-DETR at this budget.
- YOLO11s peaks at epoch 2 and then loses 0.040 by epoch 6, the largest late drop of all runs. Its validation curve is from
  Marko's CH-09 run (RTX 3050, same protocol).
- The 500-query model starts higher (epoch 1: 0.236 vs 0.222) but stays almost flat (0.236-0.244).
- With lr0 1e-4 the curve rises more slowly (0.61 of best after epoch 1) and peaks lower. With a bias warmup start of 0.1
  under AdamW, epoch 1 collapses to 0.031 and the run is still rising at epoch 6. The learning-rate log shows this:
  `results/rtdetr_lr1e4/ultralytics/results.csv`, `lr/pg2`.

## 6. Dense scenes and the query cap

`density.csv` (val_full mAP by targets per frame; maxDets 500 and 100) and `query_saturation.json`.

| run | 0-19 | 20-49 | 50-99 | >=100 targets |
|---|---|---|---|---|
| RT-DETR-l baseline | **0.128** | **0.261** | **0.275** | **0.368** |
| RT-DETR-l 500 queries | 0.105 | 0.255 | 0.266 | 0.356 |
| YOLO11s | 0.046 | 0.142 | 0.184 | 0.284 |
| Faster R-CNN RPN pre3000 | 0.072 | 0.202 | 0.228 | 0.279 |
| RetinaNet anchors | 0.095 | 0.189 | 0.203 | 0.260 |

Measured facts:
- RT-DETR has no NMS. Each decoder query returns one box, so the number of queries is a hard cap on detections per frame
  (`movd/rtdetr.py`, tested in `tests/test_rtdetr.py`). At the evaluation threshold (conf 0.001), **every** val_full frame
  returns exactly the cap: 300 (baseline) or 500 (q500). This holds for 2,846 / 2,846 frames in every density bin.
- The cap is not binding in terms of confident boxes. Detections with score >= 0.3 per ground-truth target are 1.13 for the
  baseline and 1.30 for q500. The densest val_full frame has 116 non-crowd targets, below 300.
- The maxDets choice matters for dense frames. At >= 100 targets the baseline scores 0.368 at maxDets 500 and 0.315 at maxDets 100,
  compared with 0.128 / 0.128 for 0-19 targets.
- 500 queries lowered AP in every density bin, most in the sparsest one (0.128 -> 0.105). The hypothesis written before
  training (in `configs/runs/rtdetr_q500.json`: more queries for dense frames) is not supported at this budget.
  Mechanism facts that can be checked: the extra 200 queries add no parameters (RT-DETR selects the top-k encoder features as
  queries, `learnt_init_query` False). They do change training: 500 instead of 300 predictions enter the Hungarian matching
  and the decoder self-attention (including the denoising attention mask, `get_cdn_group(..., num_queries, ...)` in
  `ultralytics/nn/modules/head.py`). Which of these explains the drop was not isolated.

## 8. Speed (RTX 5070 Laptop GPU, batch 1, imgsz 1344, conf 0.001, max_det 500)

| model | FPS, same session (`speed_recheck/`) | FPS, own run's `speed.json` |
|---|---|---|
| RT-DETR-l (300 queries) | 10.6 | 13.8 |
| RT-DETR-l (500 queries) | 10.5 | 14.1 |
| YOLO11s (CH-09 checkpoint) | 64.2 | 72.8 (`yolo11s_speed_rtx5070.json`); 36.37 on Marko's RTX 3050 |

- Absolute FPS on this laptop varied by about 20-25% between sessions (`speed_recheck/README.md`). Only the same-session
  ratio is stable: YOLO11s is about 6x faster than RT-DETR-l. The query count has no measurable speed effect.
- The Ultralytics timing scope includes CPU resizing and transfer. RT-DETR stretches frames to 1344x1344; YOLO letterboxes
  the long side to 1344 and runs NMS.
- The torchvision Faster R-CNN / RetinaNet FPS (14.8 / 19.7) use GPU-resident tensors and were timed in other sessions. They
  are not directly comparable with the Ultralytics numbers.
